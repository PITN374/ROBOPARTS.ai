## 1\. PROJECT OVERVIEW

ROBOAGENTIC is a Python platform designed to discover candidate robotics suppliers, organize supplier evidence, classify component capabilities, and support procurement workflows.

Core capabilities:

- Discover candidate robotics manufacturers through configured web-search APIs.
- Classify potential suppliers by component and manufacturing category.
- Preserve search queries, source URLs, and discovery provenance.
- Calculate preliminary robotics relevance and evidence completeness scores.
- Assess possible manufacturer, distributor, and directory roles.
- Record supplier research evidence and review requirements.
- Store candidate company and RFQ records in a database.
- Generate operational reports.
- Run scheduled background discovery jobs.
- Send optional developer reports through configured SMTP.
- Provide a foundation for multilingual discovery and future procurement agents.

**Critical limitation:** Search results and calculated scores are preliminary signals. They do not prove legal identity, domain ownership, manufacturing capability, product availability, financial stability, or suitability for purchasing.

## 4\. SUPPLIER IDENTITY RESOLUTION

File:

```
src/roboagentic/discovery/identity.py
```

This module analyzes supplied company names, websites, search titles, descriptions, and source URLs.

It returns an `IdentityAssessment` containing:

- Company name and proposed website.
- Preliminary business-role classification.
- Robotics relevance score.
- Evidence completeness score.
- Manual-review requirement.
- Reasons supporting the assessment.
- Matched manufacturer, distributor, directory, and robotics terms.
- Normalized supplier and source domains.

Possible classifications:

```
possible_manufacturer
possible_distributor
manufacturer_and_distributor_possible
unclassified
```

Directory evidence is recorded separately in the improved implementation. A business appearing in a directory is not necessarily a directory operator.

### Score definitions

`robotics_relevance` is a heuristic based on recognized robotics-related terms.

`completeness_score` measures how many of five input fields are populated, awarding 20 points per populated field.

Neither score is a probability or a measure of independently verified identity.

The module keeps `review_required=True` because its classifications are preliminary.

### Serialization

Use:

```
assessment_to_dict(assessment)
```

to convert an assessment into a dictionary suitable for JSON serialization.

The module does not independently access the internet, verify company registration, or establish website ownership.

## 5\. EVIDENCE REVIEW

File:

```
src/roboagentic/discovery/verify.py
```

The `review_candidate()` utility checks:

- Whether the supplier website is a valid HTTP(S) URL.
- Whether a source URL is available and valid.
- Whether the company name is populated.
- Whether the description is populated.

Expected statuses:

```
needs_review
evidence_recorded_identity_unverified
```

These statuses describe the availability of basic evidence, not whether the company is legitimate.

A valid URL does not prove that the website belongs to the named company. A more advanced verification module should eventually corroborate company names, official domains, corporate registrations, product documentation, and independent sources.

## 6\. LIVE DISCOVERY

File:

```
src/roboagentic/discovery/search.py
```

The discovery module uses the Brave Search API to find candidate robotics suppliers.

The intended responsibilities are:

1. Generate queries for configured component categories.
2. Send bounded-concurrency search requests.
3. Preserve titles, URLs, descriptions, queries, and categories.
4. Discard malformed results.
5. Deduplicate results without losing useful provenance.
6. Export candidates to JSON.
7. Optionally store candidates in the existing application database.

Configured component categories include:

- Actuators and servo motors.
- Mechanical components and CNC machining.
- Robotic hands and grippers.
- Wiring harnesses and electrical connectors.
- Force/torque sensors, LiDAR, and tactile sensors.
- Motor controllers, embedded controllers, and PCB assembly.

The module requires `BRAVE_SEARCH_API_KEY`.

Search results must remain unverified candidates. A search result title is not necessarily a company name, and a result URL is not necessarily the supplier's official website.

## 7\. INTEGRATE IDENTITY ASSESSMENTS INTO DISCOVERY

File:

```
src/roboagentic/discovery/search.py
```

Add these imports:

```
from roboagentic.discovery.identity import (
    assess_identity,
    assessment_to_dict,
)
```

After collecting the discovery results, generate preliminary identity assessments and export them separately.

Recommended integration:

```
from pathlib import Path
import json

assessments = []

for result in results:
    assessment = assess_identity(
        company_name=result.title,
        website=result.url,
        title=result.title,
        description=result.description,
        source_url=result.url,
    )

    assessments.append(
        assessment_to_dict(assessment)
    )

output_path = Path(
    "reports/identity_assessments.json"
)
output_path.parent.mkdir(
    parents=True,
    exist_ok=True,
)

output_path.write_text(
    json.dumps(
        assessments,
        indent=2,
        ensure_ascii=False,
    ),
    encoding="utf-8",
)
```

**Important limitation:** This first integration passes the search-result title as the company name and the result URL as both the proposed website and source URL. It is a preliminary integration only.

A production implementation should distinguish:

- `company_name`: the actual supplier name, extracted when possible.
- `website`: the candidate's official website, when identified.
- `source_url`: the page that supplied the evidence.
- `query`: the discovery query that found the candidate.
- `source_provider`: the search or data provider.
- `retrieved_at`: the time the evidence was collected.

When an official website cannot be established, retain the result URL as source evidence rather than asserting that it is the supplier's official domain.

The existing `SearchResult` dataclass should be extended if necessary to retain additional provenance fields.

The identity export must not overwrite the original discovery export.

## 9\. AUTONOMOUS DISCOVERY WORKER

File:

```
src/roboagentic/jobs/worker.py
```

The worker is intended to:

1. Initialize the database.
2. Run discovery for configured component categories.
3. Export current search candidates.
4. Generate identity assessments.
5. Optionally save candidate records.
6. Generate an operational report.
7. Optionally send a developer summary.
8. Repeat after the configured interval.

Configuration includes:

```
DISCOVERY_INTERVAL_HOURS=24
SEARCH_COUNTRY=US
SEARCH_LANGUAGE=en
SEARCH_RESULTS_PER_QUERY=10
SEARCH_CONCURRENCY=2
SAVE_DISCOVERIES=true
REPORTING_ENABLED=false
LOG_LEVEL=INFO
```

The worker should use the same discovery and assessment functions as the command-line interface. Avoid duplicating business logic.

The worker must handle repeated failures without leaking API credentials or reporting a failed discovery cycle as successful.

## 17\. MULTILINGUAL DISCOVERY ROADMAP

The next high-value module is multilingual supplier discovery.

Recommended capabilities:

- Generate translated component and manufacturing queries.
- Preserve the original query and translated query.
- Store the source language and target language.
- Record the country or region targeted.
- Preserve the original source title and description.
- Support language-aware terminology and aliases.
- Deduplicate companies across scripts and languages.
- Retain original-language evidence alongside translations.
- Measure discovery coverage by country and language.
- Track translation provider, query performance, and API cost.

Translated search results must remain candidates until their company identity and capabilities have been corroborated.

## 20\. FINAL PROJECT STATUS AND LIMITATIONS

ROBOAGENTIC is intended to be a modular robotics supplier intelligence platform. Its search, classification, database, reporting, and worker components must be integrated and tested together before the system can be considered production-ready.

The following are not guaranteed by the preliminary modules:

- Worldwide supplier coverage.
- Official manufacturer identity verification.
- Domain ownership verification.
- Manufacturing capability verification.
- Verified contact details.
- Automated quotation ingestion.
- Fully integrated multi-agent coordination.
- Uninterrupted worker operation.
- Authorized supplier outreach.

**Final principle:** Discover broadly, preserve evidence, score transparently.
